*wbx-tui.txt*  Webex engine client for Vim and Neovim          *wbx-tui*

wbx-tui uses native buffers, editing modes, windows, undo and mappings.
Node owns REST/OAuth; a separate persistent tmux process owns meeting media.
Loading this plugin never connects or captures devices.
New native behavior is implemented and offline-validated in isolated builds,
not live activated. See docs/verification-index.md for current source/gate evidence.
Earlier missing-Vim records remain historical; later strict gates cover both editors.

SETUP                                               *wbx-tui-setup*

Requires Node 22.12+ and npm. Build: npm ci && npm run build
Verify the plugin: npm run verify:plugin (builds before headless editor tests).
CI: WBX_STRICT_EDITORS=1 npm run verify:plugin requires both full Vim and Neovim.
The baseline verifier disables inherited graphical/media test opt-ins.
Add the checkout to 'runtimepath' or your plugin manager.
LazyVim: put the complete examples/lazyvim.lua spec in
~/.config/nvim/lua/plugins/wbx-tui.lua and adjust dir. Do not add a second lazy
setup or manual runtimepath entry. The spec uses opts/main and preserves your
LazyVim global save key/statusline. Use j/k and Enter to open a space, i to
compose, and Esc then <localleader>s to send. No selection command is needed.
Build a local checkout first; :Lazy build wbx-tui can rebuild it explicitly.
Vim needs +job +channel +timers; editor meetings additionally need +terminal.
Neovim uses its native job/terminal APIs. No Lua is required for Vim.
Meeting demos need Linux, tmux, Chrome/Chromium and Kitty/display or an editor
terminal. Live meetings ALSO require npm run sdk (pinned browser SDK download),
approved SDK participation rights and an authorized meeting. REST messaging and
demos do not need that browser SDK. This download is NOT install:read-status.

Common options (Vim): >
  let g:wbx_tui = {
        \ 'mappings': 1, 'send_with_ctrl_s': 1, 'statusline': 1,
        \ 'leader_prefix': '<leader>W', 'folds': 1, 'people_status': 1, 'read_status': 1,
        \ 'threaded_history': 1, 'upcoming_meetings': 1, 'message_borders': 'gutter',
        \ 'rooms_width': 30, 'compose_height': 8, 'spaces_cache': 1,
        \ 'meeting': {'display': 'auto', 'fallback': 'editor',
        \             'headless_demo': 0, 'leave_on_exit': 0}}
<
Neovim: >lua
  require('wbx-tui').setup({ meeting = { display = 'auto', fallback = 'editor' } })
<
Optional: config (explicit JSON path), backend (argv list), demo, picker.
All native/Lua-forwarded keys/defaults: docs/native-options.md, generated-key checked
against wbx#options#catalogue(). Lua-only callbacks/integrations stay local.
Notifications default to editor delivery. See |wbx-tui-notifications| for privacy,
desktop/hybrid opt-in, reminder times, independent toggles and bounded coverage.
send_with_ctrl_s defaults to 1 for compatibility. Set it to 0 to preserve your
save key without disabling navigation. mappings=0 disables both buffer defaults
and the global command family. Commands and Plug targets remain available.
If using an earlier LazyVim recipe with mappings=false, change to mappings=true
and send_with_ctrl_s=false; no user config is rewritten by the plugin.
read_status defaults to 1; set 0/false to opt out. The optional SDK must already
be installed (npm run install:read-status); nothing installs or connects for you.
The SDK needs spark:all (including spark:kms); scopes are never auto-broadened.
It runs in a separate Node process, not a browser or meeting/media owner.
With read_status=1 and spaces_cache=0, spaces and unread status load together; the first
populated list already has unread styling. The loading row remains until both
settle. SDK failure releases REST spaces with an unavailable-status notice.
The default spaces_cache=1 displays muted stale metadata sooner, then
fresh REST spaces without waiting for unread initialization; unknown stays unknown.
display: auto prefers Kitty, editor forces editor, kitty requires Kitty/display.
fallback: editor or error. headless_demo is demo-only; live headless is refused.
leave_on_exit is off by default. Crashes cannot guarantee automatic leave.
Opt-in leave-on-exit cancels queued startup and allows up to five seconds for
confirmed media-owner termination. If confirmation fails, check tmux explicitly.

Meeting status/borders inherit your tmux configuration by default. For the older
engine theme, opt into "tmux": {"appearance": "theme"} in the engine JSON.
The default is "inherit"; no global tmux appearance/keybindings are changed.

LOCAL SECTIONS AND FILTERS                          *wbx-tui-sections*

The default list stays flat. Section actions are explicit, versioned and limited
to 32 sections/500 assigned room IDs. <leader>Wvs opens their native action menu;
<leader>Wvf chooses a loaded/local filter. Named commands remain available.
One room has at most one local section. Unknown/new rooms remain Unassigned.
Filters and collapse hide rows, not the selected destination/history/draft.
Headers cannot select rooms; Enter toggles the exact local section instead.
Counts mean loaded/local rows and unread emphasis, not server totals. Collapsed
headers and the all-loaded summary retain unknown/stale provenance; no receipt
follows. Draft/reply/file badges and the drafts filter use only native memory.
Use all to return to the complete loaded list and :WebexMoreSpaces for paging.

Edits are session-only until the existing spaces_cache identity path has
verified the account/profile. Save/load/clear then explicitly use that private
key; there is no automatic save, lookup or configuration rewrite. Files contain
labels/order/collapse and room IDs only (0600 files/0700 directory). Load rejects
corrupt/foreign/version-mismatched documents without changing current grouping.
Local preferences do NOT import/sync native Webex Sections or mutate server Teams.
Previously saved grouping restores after the existing verified identity path
only into an empty, unchanged session. Edits/clear/opt-out/account changes cancel
late loads. No additional identity read, autosave or message-body persistence.
See docs/local-sections-design.md for budgets, persistence and offline evidence.

Presence defaults on in the selected-DM float, header and Spaces icons; no command
is required. :WebexPeople opens native read-only local details; the float is separate.
Active means recent activity, not
guaranteed availability; stale/unknown/unavailable stay explicit. No roster-wide
poll, inferred offline/busy, audio/video call distinction or custom-status text.

LOCAL MESSAGING VIEWS                               *wbx-tui-local-messaging*

<leader>Wab toggles a local bookmark; Wvb lists them. At most 128 exact identities,
no stored bodies, no disk or Webex Flags sync. Disconnect/new session clears them.
Choose/load the original selected space explicitly before jumping to a source.
Wvh opens the loaded thread, ALWAYS partial even when its root is present.
Wvg lists loaded file messages; :WebexContent links or media changes the filter.
These lists perform no fetch, download, URL opener, mutation or receipt.
Enter jumps only to exact, currently loaded, unchanged main history. Use Reply,
Quote or attachment commands there. r explicitly regenerates; q returns; / searches.
Annotations/promoted buffers/user mappings are retained; mappings=0 disables defaults.

Waq captures bounded copied text from unchanged main history; Wai inserts it at
the END of the SAME selected space's plain normal/reply draft. No silent format,
destination or mention consent change. Attribution is a copied display label,
not verified authorship/native service quote. Mention delimiters are neutralized.
At most 3000 source bytes/eight sources per draft, with the normal 1000 UTF-16 /
4000-byte final draft limit. Oversize refuses without truncating or partial edits.
Native undo removes only the insertion; previous typing remains undoable.
Send remains explicit and rechecks exact source/session/accessibility. If source
is changed/unloaded after insertion, recapture or explicitly :WebexQuoteDetach
(confirmation defaults to Cancel) to keep ordinary manually copied text.
Detach never sends or edits the text/undo. Source guards may conservatively remain
after native undo; detach explicitly when no longer wanted.
An older backend without local-context-v1 explains unavailability, never guesses
the account/session. These views are not server search, complete thread retrieval,
remote galleries, multi-account support, pins or native Flags. Normal/reply draft
recovery is a separate, default-on private plaintext feature; see
|wbx-tui-drafts|.

REMOTE THREADS AND SELECTED-SPACE MENTIONS            *wbx-tui-message-queries*

<leader>WvH / :WebexThreadFetch reads the source under the cursor afresh, its root
when distinct, and ONE replies page (at most three GETs). Wvh stays loaded-only.
<leader>Wvi / :WebexMentions explicitly queries API @me results in the selected
space. This is NOT an account-wide inbox and @all coverage is unverified.
Known spark:messages_read/spark:all, a ready selected space, local-context-v1
and message-queries-v1 are required; older backends cannot guess a provider.
r refreshes explicitly; ]p fetches ONE next page; q returns; / searches loaded text.
No per-keystroke/background lookup, automatic paging, retry or scope expansion.
50 items/page, five pages/250 replies (+root) or mentions, 256 KiB retained item
data/query, two-minute lifetime. Partial and budget/cycle/clipping labels remain
visible. API exhaustion means at observation, not an atomic/future-complete view.
Changed/nested/wrong-room source/root data refuses without inventing ancestry.

Enter in mentions opens inert retained text (zero requests); Enter in a remote
thread/detail jumps only to an exact already-loaded unchanged main-history ID.
Unloaded/clipped targets never trigger a hidden fetch/room switch or nearest row.
An exact reply hidden inside another thread's closed fold is refused rather than
substituted with the root; open that native fold explicitly. Result jumps reset
the paging baseline, so they cannot masquerade as upward edge motion and fetch.
Files/actions and unsupported card content are omitted, not registered or opened.
Supported card text can appear as inert body text. No query results enter
main history, newest endpoints, notifications, unread state or receipt evidence.
Rendering, opening/scrolling lists and status/help never mark anything read.

WaR / :WebexThreadReply works in loaded history and, in a current queried thread,
reuses the existing exact-root
reply draft only while main history still references that verified root. Normal
and reply text/full native undo remain separate. Enter/write still NEVER sends;
existing explicit send, grant/parent/destination/one-shot/ACK checks stay in charge.
Mentions cannot authorize arbitrary reply targets. Use main-history Reply there.
Old account/room/selection epochs (even away-and-return), late results, expiry,
annotations and promoted buffers cannot retarget requests or drafts.
Live tenant/filter behavior is unverified; provider/security gates remain.

JOINED TEAM LIST                                    *wbx-tui-joined-teams*

<leader>WvT / :WebexJoinedTeams explicitly reads Teams the authenticated user
belongs to. This is NOT public/organization discovery, native personal Sections,
Team management or room membership/role proof. Existing Wvt / :WebexTeams keeps
its loaded-room association label semantics; the joined query is separate.
Requires joined-teams-v1/local-context-v1 and already-known spark:teams_read or
spark:all. Missing support/grants explain unavailable, never reconnect or expand.

r / :WebexJoinedTeamsRefresh starts a fresh same-session query, including when
retained text is old. ]p / :WebexJoinedTeamsMore fetches ONE exact-revision page.
q returns; / searches loaded text. No per-row, render, status or help-triggered
requests, automatic pagination, retry, Team-detail or room/member scans.
50 items/page, five pages/250 IDs, 64 KiB retained item JSON, two-minute query
lifetime from first observation. Native JSON re-encoding remains bounded at
128 KiB without raising the Node quota. Budget/cycle exhaustion stays PARTIAL.
API exhaustion means at observation, not an atomic/current membership census.
Labels are sanitized/clipped presentation only; exact IDs disambiguate names.
Descriptions, roles, members, raw payloads, tokens and admin data are excluded.

Enter / :WebexJoinedTeamFilter only filters currently loaded noncached spaces
by the exact selected Team ID, through the existing local filter owner. If none
are loaded, it explains the limit, NOT that the Team has no spaces. It never
fetches rooms, selects a draft destination, joins/invites/posts or marks read.
Old-session/stale/future/late/away-and-return/annotated/promoted results cannot
silently install or retarget; old-session refresh/paging refuses. Clean unload
restoration, user mappings/prefixes/opt-outs, native draft text/undo and independent
meeting owners are unchanged. Live tenant/grant acceptance remains unrun.

READABLE CARD TEXT                                  *wbx-tui-cards*

Supported Adaptive Cards versions 1.0-1.3 display an explicitly read-only text
subset in ordinary history: TextBlock, FactSet and nested Container/Column trees.
Card strings are literal, not executable Markdown/HTML/templates/Ex/JavaScript.
Existing plain/rich fallback text remains first. Unknown/new versions/elements,
hidden/conditional subtrees, input defaults/IDs/data, actions and nested ShowCards,
refresh/auth, images/media and URLs are never traversed, fetched or submitted.
Generic omission/partial labels replace unsupported content, never raw JSON.
This is readable content, NOT full layout support or an interactive card form.

<leader>WvC / :WebexCards / :WebexContent cards lists only LOADED card messages.
adaptive-card-text-v1 and local-context-v1 are required for this list; older
backends explain absence rather than infer cards from body labels.
Enter jumps to the exact loaded unchanged main-history message, NOT an action,
URL or form. r regenerates locally; q returns; / searches already-loaded text.
No new RPC, receipt, provider query, input collection or permanent pane.
User mappings/opt-outs, annotations/promoted views, native undo/folds, session
and destination guards are unchanged. Compatibility clients receive inert text
only; these keys are for Vim/Neovim.

Per message: ten content attachments inspected, 32 children/array, 128 nodes,
depth eight, 2048 UTF-16 units/visible field, 4096 units/16384 bytes of card text.
Combined message/card display stays within the existing 10100-unit budget.
Limits are explicitly labeled, not silently treated as complete card content.
Main-history metadata is only an inspected card count and partial flag, never
an action ID, raw input, URL, provider role or write/receipt authority.
All card actions require an independent future provider/privacy contract.

TEXTUAL PERSON PROFILES                             *wbx-tui-profiles*

<leader>WnP / :WebexProfile opens an on-demand TEXT profile for the exact current
directory/member row ID, never its name/label. Or use :WebexProfile exact-person-ID
explicitly; no name/email resolution, selected-peer probe or organization scan.
An updated backend with people-profile-v1/local-context-v1 and an already-known
spark:people_read/spark:all grant is required. No grant expansion or reconnect.

Only display name, first name, last name, department, title and time zone are
projected (120 Unicode characters/480 bytes each; 4096-byte DTO maximum).
Missing, normalized or clipped fields are PARTIAL, never inferred. Exact ID and
observation time stay visible. Private email/phone/org/admin data, status,
lastActivity, custom status and avatar URLs are excluded. No avatar is fetched.
This does not add self status/DND/profile writes or alter automatic presence.
people_status=0 and sender_names=0 do not disable an explicit text-profile read,
and the read never enables/enriches either automatic feature or notifications.

r / :WebexProfileRefresh makes ONE fresh GET for the same ID/session, including
when retained text is old. q returns; / searches; Enter is not a profile action.
No background refresh, per-row/cursor request, write, receipt, DM or opener.
Responses older than two minutes or future-dated beyond clock-rounding tolerance,
old sessions, changed source rows and late/away-and-return choices cannot install.
An old-session roster cannot supply a new-session profile target; refresh it first.
Annotated/promoted buffers, user maps, mapping opt-outs, focus, unrelated draft
text and full native undo are preserved. Close/rename annotated views explicitly
before generating another profile. Retained profile text is not action authority.
Live profile/tenant/grant acceptance remains separate from offline verification.

DIRECTORY PREFIX SEARCH                             *wbx-tui-directory*

<leader>Wnp / :WebexDirectory prompts once for a literal name PREFIX (not substring).
2-120 characters/480 bytes maximum; no empty/wildcard/organization enumeration.
No per-keystroke requests, automatic refresh, presence/avatars or scope expansion.
Uses already-known spark:people_read/spark:all through the fixed public REST owner.
directory-search-v1 and local-context-v1 are required; old backends explain absence.
50 results/page, five pages/250 identities maximum, query expires after two minutes.
Partial/policy-limited results are not a directory census; no hit is not absence.
Same-name rows show distinct exact IDs. r explicitly refreshes that prefix; ]p
requests only its next bounded page. Enter prepares a plaintext DM for the exact
row ID via the existing fresh identity owner, not a name/email. It NEVER sends,
posts a placeholder, invites, joins a space or marks anything read.
q returns; / searches already-loaded text. Annotated/promoted lists and user maps
are retained. Lost/late/session-changed/expired results cannot target another user.
No emails, phone numbers, roles, licenses, avatars or presence are retained in
directory projections. Live tenant/grant policy acceptance remains separately gated.

OUTGOING FILES                                      *wbx-tui-uploads*

Use :WebexAttach in a ready normal/reply composer. The command chooses a local
regular file and stages a stable snapshot, never sends it. File name/size appears
in the statusline, not in sendable text. Enter/write/removal never sends.
:WebexSend explicitly sends text plus the file, or a file alone.
For Markdown plus ONE file, choose :WebexFormat markdown, stage with :WebexAttach,
then use the same :WebexSend / <localleader>s binding. Enter still inserts a
newline; writing never sends. A Markdown caption must be nonblank and within the
existing 1000 UTF-16 / 4000 UTF-8 byte limit. Plain file-only sends are unchanged.
<leader>Wua/ur stage/remove; Wuc/us cancel/status. Existing attachment
open/download commands are unchanged.

Symlinks (including parent paths), hardlinks, directories/FIFOs/devices, changed
files and files over 10 MiB are refused. Original-file edits/replacements after
successful staging do not alter the anonymous read-only snapshot. At most eight
snapshots/20 MiB aggregate, one stage and one physical upload, no automatic queue.
